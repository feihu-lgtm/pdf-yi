# PDF译 v65.0

打开 PDF → 后台翻译 → 自动生成「左边原版、右边译文」的双栏 PDF。
- 本地打开的 PDF：双栏 PDF 自动存在原文件旁边，叫「原文件名_双栏.pdf」。
- 在 Zotero 里右键翻译的：双栏 PDF 自动挂回同一个条目。原附件存在 Zotero 里，就复制进 Zotero；原附件是链接到外部的文件，就存在原文件旁边、以链接挂上。
- 你在阅读器里做的高亮和批注，写成真正的 PDF 批注，放在左边原文上。

两种用法，同一份页面代码：

| | 轻量版 | Mac 程序 |
|---|---|---|
| 打开 | 双击 `启动PDF译.command`，在浏览器里 | 双击 `PDF译.app`，独立窗口 |
| 编译 | 不用 | 要，在 Mac 上用 Tauri 编译一次 |
| 后台翻译、菜单栏 | 没有 | 有：关窗口不退出；菜单栏的小鱼按状态换表情，旁边显示「31/60」，可以暂停 |
| 双栏 PDF 存到哪 | 浏览器下载 | 原文件旁边（自动），手动导出弹「存储为」 |
| Zotero 右键翻译 | 不支持 | 支持（要装 `PDF译-zotero.xpi`） |

都要先开着本机的 Magpie 反代（`http://127.0.0.1:3426/v1`）。

## 〇、架构（v53 起是双架构）

| 部分 | 文件 | 做什么 |
|---|---|---|
| 全量版（读书用） | `www/index.html` | 阅读、高亮批注、纯文本/三栏、AI 对话、导出……所有功能 |
| 后台面板与隔离引擎 | `www/worker.html` + `www/worker.js` | `worker` 只显示菜单栏仪表盘；`engine-1..4` 是永不显示的独立 WebView，每个引擎一次翻一本，核心模块的整本状态互不干扰 |
| 核心模块 | `www/core/textutil.js` `store.js` `extract.js` `translate.js` `bilingual.js` | 后台先整本本地提取、清理、分段，再批量确认分段、跨页装箱翻译；逐页缓存格式与阅读器兼容 |
| 模型网络传输 | `www/model-http.js` + Rust `model_http` / `request_limiter.rs` | 阅读器、面板和全部引擎共用原生 HTTP 连接池及同一个发送许可池；术语表、合并、翻译、CSL 同样受限。轻量浏览器版仍用 fetch，不具备跨窗口原生总上限 |

- 两边共用同一份缓存（IndexedDB `PDFTransCache`）和设置：后台翻过的书，用全量版打开直接有译文。
- 后台任务由 Rust 接收、按路径查重并保存在共享待办列表。空闲引擎一次只领取一本，领取和并发上限检查在同一把锁里；启动时也来领取，不依赖先前是否收到通知。
- 默认同时翻 2 本；后台面板「菜单栏」里的「同时翻几本」可选 1 / 2 / 3 / 4，修改用于后续领取任务。另一项「同时最多发几个请求（所有书合计）」与阅读器及 `pdfyi_conc` 共用，默认 24，范围 6–64；`pdfyi://settings?conc=24&books=2` 无窗口修改。所有引擎和阅读器合计不超过原生上限，不再每本相乘；调低不取消在途请求，先排空到新上限以下再发。
- 所有引擎窗口都设 `backgroundThrottling: disabled`，并跳过任务栏；面板收起不影响翻译。这个 WebKit 选项要 macOS 14 及以上，13 及以下没验收。
- 引擎把每本的书名、来源、逐页状态、页数、失败和 ETA 交回 Rust，面板列出所有正在翻的书；菜单栏显示合计进度和共享排队数。暂停/继续对全部引擎生效。最近结果由 Rust 集中更新，只有面板镜像写旧版 `pdfyi_recent`，避免多本完成时互相覆盖。
- 阅读器启动时隐藏；`LSUIElement` 与启动事件循环之前设置的 Accessory 激活策略保证后台链接不露窗口、不抢焦点、不闪 Dock 图标（不能等到 setup 才改，否则 Tao 会先短暂应用默认 Regular）。冷启动由 AppKit 的 `NSApplicationLaunchIsDefaultLaunchKey` 明确区分普通打开与链接打开，并等待 Tauri Ready；不是靠计时猜测，延后到达的 open-url 也不会先露窗口。主动打开阅读器切到 Regular，隐藏或关闭阅读器回到 Accessory。
- 翻译调度和面板状态更新由事件驱动，不依赖隐藏窗口计时器；菜单栏「打开后台面板」看全部任务和日志。引擎开始/结束时间另存到应用日志目录的 `engines.log`。
- Mac 模型请求取得共享许可后，原生网络超时 300 秒（等待许可不占网络连接）。生成双栏 PDF 前，对网络、HTTP 429 和 5xx 的失败段落退避 2 / 4 秒、最多再试两轮；已成功段落不重翻。网页的固定 64 个任务预取窗只限制 IPC 排队内存，不是每本的发送上限，真正发送仍统一由 Rust 许可池控制。
- 引擎所有 `ok=false` 日志追加到 `~/Library/Logs/com.xiaohu.pdfyi/failures.log`，包含时间、引擎、书名、页码、类型和最多 300 字的单行消息。已有失败缓存不冒充翻好页，重新领取时自动重翻。
- 双栏 PDF 一次复制整本原页、共用字体和图片（v54）：大小和原文件差不多；没旋转的页保留原 PDF 自带的链接和批注。

```bash
xcode-select --install
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
cargo install tauri-cli --version "^2" --locked
```

**编译**

```bash
cd PDF译/mac-app/src-tauri
cargo tauri build
```

产物：`mac-app/src-tauri/target/release/bundle/macos/PDF译.app`。把它拖进「应用程序」。
程序没有签名，第一次打开要右键 → 打开，或者 `xattr -cr "/Applications/PDF译.app"`。

**一定要先打开一次 PDF译.app**，macOS 才会记住 `pdfyi://` 链接由它来打开，Zotero 插件才叫得起它。

调试：`cargo tauri dev`。

## 三、Zotero 插件

1. Zotero 7：工具 → 插件 → 右上角齿轮 → 从文件安装插件… → 选 `PDF译-zotero.xpi`。

4. 翻完，条目下面多一个「原附件名_双栏」的 PDF。同一条目再翻一次，旧的那份会被移到回收站、换成新的。

要求：Zotero 开着；Zotero 的本地服务（127.0.0.1:23119）是默认开的，浏览器插件也用它。

## 二之十八、v65.0：先切后发与全局请求上限

- Phase A 不联网：整本先提取、识别清理规则、处理跨页补句，并为每页生成段落和框；用时显示在引擎日志的 `phaseAMs`。Phase B 再做术语表和模型请求，面板区分「本地分段」「批量确认分段」和翻译，进度格子、ETA、续翻仍按页。
- 保留模型合并但跨页装箱：每批约 6000 字符 / 240 原始行，标明页界；结果必须按顺序完整覆盖每行，页界处再次强制分开。请求失败、漏行、重复或乱序时沿用版面细分回退，不取消分段保障。
- 翻译按全书阅读顺序装箱，跨页共用最多 3000 字符 / 24 段；超长原段拆成多个请求片段，全部完成后合回原来的一段。保留 `[n]` 编号、每批术语子集及最多三层的截断/错位拆分重试。每页所有片段完成才写原来的 `:enN` / `:pN` 缓存，优先提交原文分段；干净缓存原样复用。
- 原生共享发送上限默认 24，范围 6–64，后台和阅读器都可调；设置链接也有效。降低上限先等在途请求结束；取消网页调用不会提前归还仍在执行 HTTP 的许可，出错或 panic 都会归还。HTTP 429 继续用既有两轮退避，没有新增未经实测的自适应策略。
- 取舍：翻译请求中的邻文现在可以跨页，因此不保证逐字等同旧版逐页翻译；每段的缓存、页码、原文框和全书术语约束不变。合并和术语表阶段仍有网络等待，本地先切不代表整本立刻翻完。
- 回归命令：`node tools/tests/book-packing.cjs`、`node tools/tests/segment-first.cjs`、`node tools/tests/transient-retries.cjs`；原生共享限流测试：`cargo test --locked --manifest-path mac-app/src-tauri/Cargo.toml request_limiter::tests`。真实 PDF / 真实模型、不开窗口的对照脚本：`node tools/tests/pipeline-benchmark.cjs PDF OUTPUT_PREFIX [source-www] [cap=24]`，只输出数值指标，不输出书中文字。

2026-10-30 实测：同一份已有的 23 页英文学术 PDF 的两份临时副本，均空缓存、上限 24、真实 Magpie 请求。Node 回放执行实际 worker/core 和双栏生成，HTTP 传输在同一回放器里限为 24，便于比较算法；原生多引擎总上限另外用安装后的 App 验证。以下是单次对照，不把服务端响应波动当作稳定性能承诺。

| 指标 | v64.2 逐页 | v65.0 先切后发 |
|---|---:|---:|
| 整本含双栏生成 | 182.63 s | 130.66 s（少 28.5%） |
| 独立 Phase A | 无（分段与请求交错） | 111 ms |
| 同步提取/分组处理累计耗时 | 21.84 ms | 20.22 ms |
| 合并请求 / 平均延迟 | 23 / 11.54 s | 17 / 15.51 s |
| 翻译请求 / 平均延迟 | 39 / 23.78 s | 28 / 23.19 s |
| 术语表请求 / 平均延迟 | 1 / 20.44 s | 1 / 16.15 s |
| 翻译每批平均字符 / 段数 | 1907 / 7.64 | 2657 / 10.29 |
| 3000 字符预算平均填充率 | 63.6% | 88.6% |
| 请求峰值 | 23 | 24 |
| 失败标记 / 缺失译文 | 0 / 0 | 0 / 0 |
| 双栏输出页数 | 26 | 26 |

合并保留并改成跨页批量，而不是直接取消：旧版合并有 23 次、平均 11.54 秒的远程等待，相比毫秒级本地分段明显昂贵；批量后少 6 次，但没有实验证据证明单靠规则能同样可靠地处理所有版面，因此保留原有模型判断和失败回退。两次段落数为 298 / 288，分组粒度会随模型上下文变化；均逐段有译文且无失败。输出 26 页是原有「双栏论文按栏对照」把其中 3 页各拆成两张，前后相同，没有新增续页。

安装版另外同时翻两份不同的临时英文 PDF（23 / 22 页）：两个引擎相隔 6 ms 开始，完成均为 0 失败；本地 Phase A 为 1.861 / 1.204 s。对主进程到 `127.0.0.1:3426` 的已建立连接用 `lsof` 连续采样 254 次（218 次非零），峰值 **24 ≤ 设置 24**；同时用 CoreGraphics 采样可见的普通/浮动窗口，峰值 **0**。双栏结果为 26 / 22 页，同一份 23 页文档仍与旧版输出同为 26 页，输出中失败标记均为 0。

上限另存原生 `request-concurrency.json`，下次启动先载入再领取任务；首次从旧版迁移时，必须先等面板或阅读器把现有 `pdfyi_conc` 交给 Rust，避免保存的 6 暂时按默认 24 发送。



## 二之十七点二、v64.2：原生模型请求与暂时错误自动重试

- 修复两本各并发 24 时连续出现「网络错误 Load failed」：WebKit 的 HTTP/1.1 每主机连接上限由全部 WebView 共享，排队请求会耗尽网页请求超时。Mac 模型调用现改走原生 HTTP 连接池，超时 300 秒，支持已配置的 Magpie/OpenAI 等提供方；阅读器和后台一致，轻量浏览器版保持原样。
- 生成双栏 PDF 之前，网络、429 和 5xx 失败最多额外重试两轮，按 2 / 4 秒退避，沿用每本的请求并发。只补暂时失败的段落，不覆盖成功译文，不循环重试读不出字或模型格式错误；每轮在面板记一条汇总。
- 失败日志自动落盘到 `~/Library/Logs/com.xiaohu.pdfyi/failures.log`；进度日志同时标明有效缓存、待重翻失败缓存和重试轮次，便于确认续翻而不是复用失败标记。
- 回归检查：`node tools/tests/transient-retries.cjs` 覆盖分类、两轮退避、段落保留、失败计数、并发上限、HTTP 状态保留及原生/浏览器传输分流。

## 二之十七点一、v64.1：后台直接调请求并发

- 后台面板「同时翻几本」旁新增「每本同时发几个请求」，与阅读器共用同一设置。修改后当前正在翻的每本书都会从下一次派发页面起采用新并发，不必停书或露出阅读器。
- 支持无窗口设置链接 `pdfyi://settings?conc=24`；可加 `books=2` 设置同时翻几本。设置链接由 Rust 接收并保留到面板就绪后应用，不创建翻译任务、不激活窗口。
- 重启后继续使用 IndexedDB 中已翻好的页面；引擎日志记录请求并发、缓存页数和关键进度，便于确认缓存续翻。

## 二之十七、v64：同时翻多本与后台不露窗口

- 多本书分别在独立隐藏引擎里翻，互不串页、互不覆盖整本状态；面板同时展示每本的逐页格子、来源、完成页数、还要多久和失败，菜单栏显示总进度，暂停/继续控制全部引擎。
- 后台面板「菜单栏」新增「同时翻几本」，默认 2 本，可选 1 / 2 / 3 / 4；设置立即用于下一批领取任务，无需重启。每本书自己的请求并发保持原设置。
- Zotero 插件改用 `open -g` 发送链接。无论冷启动还是已经开着，后台翻译都不自动露出阅读器、不抢焦点、不显示 Dock 图标；双击正常启动、点击 Dock、菜单「显示窗口」和面板「打开阅读器」仍会打开阅读器。关掉阅读器只隐藏，不影响后台任务。
- 任务领取、按路径查重、进度聚合和最近结果统一由 Rust 管理；翻完后仍逐本存盘、通知或挂回 Zotero。


## 二之十六点一、v63.1：接口安全加固与元数据识别

- 拦截网页跨域请求：`/pdfyi/import` 与 `/pdfyi/attach` 只要收到带有 `Origin` 请求头的调用一律拒绝（403）。
- 本地防伪口令：生成 `~/.pdfyi-token` 共享口令文件，所有请求必须携带 `X-PDFYi-Token`，口令不匹配或缺失严格拒绝。
- 完善文献题录链路：有 DOI 走出版方正式元数据抓取；无 DOI 由模型提取 CSL-JSON 建立条目；均不可用时平滑降级创建普通条目，绝不报错中断。

## 二之十六、v63：加入 Zotero

- 后台面板“最近翻好”的本地 PDF 可直接加入 Zotero；原文与双栏 PDF 同时导入，同一原文再次点击不会重复建条目，只替换双栏附件。
- 条目元数据：优先从首页提取的 DOI 按出版标识符查询正式元数据；无 DOI 时由模型提取 CSL-JSON 建立条目；均不可用时降级建立条目并在后台异步识别。
- 插件在导入与挂回前校验 PDF 文件头 `%PDF-` 与末尾 `%%EOF`，不完整文件拒绝写入 Zotero；失败写入面板日志。

## 二之十五点二、v62.3：安全顺排兜底

- 删掉 4pt 强制塞入旧排法；若钉框排法（整页 R → 少数段缩至 5pt / 1.15 行距 → 借底边距）仍放不下某一行，该张整张改用顺排，统一缩放至完全入界，最小 3pt，段间留半行间距。
- 顺排画完执行自查：核验所有文字基线在页面边距以内，且输出中文字数与输入段落完全一致，自查结果计入日志。

## 二之十五、v62.1：零续页且不丢字

- 先计算每段能放下的最大字号比例，取第 80 百分位作为这一页正文的统一比例；放不下的少数段才单独缩小。
- 最低 5pt、行距最低 1.15；仍放不下时只让该段进入 4pt、1.1 行距兜底，并把页码和段落开头写入面板日志。
- 不再为译文创建续页。最后只借用原页底边距，仍不跨过下一段原文框，因此不会与相邻段落叠字。

## 二之十四、v61：页眉与合并失败回退

- 阅读顺序按空白切块（XY-cut）：最宽的空白带先切，竖向空白 ≥8pt（只剩一行时 ≥15pt）且两边有字时优先竖切；块内按行从左到右。首页这种“左边关键词、右边摘要”同一基线的版面会各自分区读取，不再拼成一段。
- 双栏页被阅读顺序拆开的页眉页脚仍按实际最高、最低基线识别并自动清理，不会把右栏页眉插入正文。
- 模型合并请求失败时，仍按原文空行、首行缩进、短末行和行距变化细分，而不是退回整栏大段；失败原因显示在后台面板日志里。
- 真实数据回放脚本在 `tools/tests/`：`real-replay.py` 用真实 PDF 与真实译文回放，`real-refine.py` 查看整页被合并后如何细分。

## 二之十三、v59：后台面板挂在菜单栏小鱼下面
- 左键点菜单栏的小鱼，下面弹出后台面板；点别处收起（面板藏起来照样在翻）。右键点小鱼还是原来的菜单。
- “现在”：正在翻的书，每一页一个小方格（翻好、正在翻、有失败、读不出字一眼看清），页数和还要多久；“添加 PDF”“打开阅读器”；排队的书；最近翻好的书（打开、在访达中显示）。
- “日志”：时间线，翻译和合并只写一句摘要（“翻好 12 段，共 504 字”），点开看模型原文；可以只看出错的、只看引擎的；一键复制给小宝或 Claude。
- “菜单栏”：自己选上下两行各显示什么（百分比、页数、还要多久、失败的页、排队的书、不显示），要不要小鱼的脸和状态符号，有失败时要不要提醒；浅色和深色菜单栏的实时预览。
- 跟着系统的浅色、深色模式。


## 二之十二、v58：每段的框照搬原文；修串页

- 修复（小宝定位）：按栏拆开的两张共用了同一个内容列表数组，译文互相串、原文被盖。现在每张的内容列表和批注列表都单独拆开（原始内容流仍共用）。
- 每段的框照搬原文的左右范围和高度，右半边同位置同大小；不再先判断整页是不是两栏，上半通栏、下半两栏的首页也能镜像。
- 字号从每段原文自己的字号起步，整页统一缩放比例；放不下的段落单独再缩（最小 6pt）。

## 二之十一、v57：每段钉在自己的框里（学 zotero-pdf2zh 的对齐原理）

- 每段译文只能用“它原文第一行的位置到下一段原文的位置”这块地方，放不下就只缩这一段的字号（最小 6.5pt），谁也推不动谁，一段对一段；同一栏里后一段不会叠在前一段上。
- 双栏但没按栏拆开的整页：右半边也分两栏镜像排，横跨两栏的标题、摘要、图注横跨整个右半边。
- 代价：同一页各段字号可能不同（原文密的段，译文字小一些）。真放不下的才进续页（测试里只剩几十字的零头）。

## 二之十、v56：自动术语表

- 开始翻译前，从前 5 页正文（最多 6000 字符）请模型挑出最多 40 条会反复出现的术语和人名、地名、机构名，给出中文学界通用译法；存进这本书的缓存，下次不再提取。
- 每批翻译只附上这一批里实际出现的术语（最多 25 条），全书同一个词同一个译法。提取结果在日志里（类型“术语表”）。设置“自动术语表”可关。全量版和后台引擎都用。

## 二之九、v55：双栏论文按栏对照

- 两栏排版、中间没有通栏内容的页，拆成两张：左栏一张、右栏一张，每张是“这一栏原文 + 这一栏译文”；每一栏按文字实际所在范围切，译文区是这一栏的 1.35 倍宽、行距 1.38 倍。
- 好处：每张约是原页的 1.2 倍宽，按宽度看时比整页双倍宽的排法大得多；每一栏的译文紧挨着原文。
- 有通栏内容的页（第一页标题和摘要、横跨两栏的图注）、旋转页、单栏页仍按整页排。设置里“双栏论文按栏对照”可以关。
- 原页仍是整本一次复制、资源共用；原 PDF 的批注和你的高亮只保留落在这一栏里的。

## 三之〇、v52：状态符号单独放大

- 画里的 Zz、气泡、灯泡从图上抠出来，和暂停的两条竖杠一起放大到接近文字的高度，排在两行字前面；小人的脸只用来认出这是 PDF译。
- 空闲“脸 + Zz”；翻译中“脸 + 气泡 + 40% / 约 6 分”；暂停“脸 + 竖杠 + 暂停 / 40%”；生成和完成“脸 + 灯泡 + 生成 / PDF”“完成 / ✓”。
- 图在 www/vendor/tray/（face-*.png 是脸，sym-*.png 是符号）。

## 三之一、v51：菜单栏“小鱼 + 两行小字”

- 翻译中：上“40%”（有排队“40% +1”），下“约 6 分”或“12/30”；有失败下一行“⚠2 页”。暂停：“暂停 / 40%”。生成：“生成 / PDF”。完成：“完成 / ✓”。空闲只有小鱼。
- 页面把图标和两行字画成一张模板图交给菜单栏（macOS 自带的文字只能一行）；图标去掉留白，撑满菜单栏高度。

## 三之二、v49：页面绘制按需进行（小宝实测的热点）

- 小宝实测：翻译时 WebKit 页面进程峰值 162.7%，Magpie、3426 反代、SSH 隧道几乎是 0。
- PDF 页面只画眼前前后一屏半的那几页，离开五屏以外就释放画布；窗口藏起来时停画。30 页的书打开时只画 2 页（v48 是 30 页全画）。
- API 日志只在设置面板打开时生成。

## 四、v48：减轻发热

- 翻译按字数分批：每次最多约 3000 个英文字符（最多 24 段），一般一页一次；请求次数大约减半，一页的段落放在一起翻，前后文更连贯。
- 输出被截断或有段没对上时，把没翻好的几段对半拆开重翻，最多拆三层，不留半截译文。
- 并发：v50 起按小狐的决定改回默认 6，可选 6 / 8 / 10 / 12 / 16 / 20 / 24 / 30（v48、v49 存下的 2、3、4 自动变成 6）。
- 发给模型的请求之间至少隔 200 毫秒，不会一瞬间全打出去。

## 四之二、v46 新增

- **逐页进度**（小宝的补丁）：顶栏「逐页进度」按钮，列出每一页的状态和段落数，点一页跳过去；译文栏每页标签上有状态徽章。
- **双栏 PDF 的旋转页和裁剪盒**（小宝的补丁）：0°、90°、180°、270° 加裁剪盒，左半边和原页逐像素一致。
- **切换文件时丢弃旧回调**（小宝的补丁）。
- **菜单栏**（v47 换成小狐画的四张小鱼）：空闲是「睡着了」，翻译中是「在思考」，暂停是「平时」，生成双栏 PDF 和完成是「来灵感」；原图在 design/menubar-icons/。旁边的字：翻译中「31/60」，有失败「⚠2」，排队「+1」，暂停「暂停 31/60」，生成双栏 PDF「生成中」，完成「完成」。点开：书名、进度和还要多久、失败的页（点了打开逐页进度）、排队的书、暂停 / 继续、打开上一份双栏 PDF、在访达中显示、显示窗口、翻完通知我、退出。
- **暂停**：不再发新请求，路上的照样翻完；继续以后接着翻。
- **完成通知**：存好或挂回 Zotero 以后弹系统通知，可以在菜单里关掉。

## 五、请小宝重点测的

1. **反代跨域**：要允许 `http://127.0.0.1:3427`（轻量版）和 `tauri://localhost`（Mac 程序）两个来源。
2. **编译**：`cargo tauri build` 能不能过。报错把原文贴过来。
3. **后台翻译**：开一本 100 页以上的书，翻到一半关窗口，十分钟里看菜单栏的数字有没有一直在走。已经在 Info.plist 里关掉了 App Nap，但网页视图藏起来以后会不会被 WebKit 自己降速，要实测。
4. **Zotero**：
   - 存在 Zotero 里的附件：右键翻译，翻完条目下面多一份「…_双栏」，能打开。
   - 链接到外部的附件：翻完原文件旁边出现「…_双栏.pdf」，条目下面多一个链接附件。
   - 同时选三个条目右键：默认两本同时翻，第三本等空闲引擎，全部挂回原条目。
5. **本地打开**：用「打开文件」按钮或者把 PDF 拖进窗口，翻完原文件旁边出现「…_双栏.pdf」。
6. **菜单栏**（v47）：四种表情在浅色和深色菜单栏里都看得清，跟着状态换；翻译时数字在走；点「暂停翻译」后不再发新请求，「继续翻译」后接着翻；翻完有系统通知；「在访达中显示」能定位到双栏 PDF。
7. **逐页进度**（v46）：面板里的状态和实际一致；点页号能跳过去。
8. **译文字号**：设置里「双栏 PDF 译文字号」小 / 中 / 大，默认中（12pt）。在「预览」里按适合宽度看，右边中文和左边原文差不多大。

## 六、已知的限制

- 双栏 PDF 只支持 PDF；扫描件没有文字层，右边写「读不出字」。
- 原 PDF 自带的批注和链接不会带到双栏 PDF 里。
- 旋转过的页面（/Rotate）没测过。
- 后台任务只认 PDF；Zotero 交来的如果是别的格式会跳过。
- v64 已在本机安装版验收普通启动、冷链接不露窗口、不显示 Dock、两本并行与第三本排队，以及本地双栏 PDF 的有效性。为不打断正在使用的 Zotero，本次只重建插件包，没有重启/重装插件，也没有向真实 Zotero 库写入验收数据；真实附件挂回仍需使用时确认。
